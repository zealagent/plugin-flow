# Agent instructions (Zealagent Plugin Flow)

Zealagent Plugin Flow is a **pnpm monorepo** for `zla-flow`: a PM/Reviewer build workflow with
a human approval gate at every step (BRD → Plan → delegated coding → Review → Commit). It ships
one plugin per agent platform: **Claude Code** and **DeepSeek Harness**. Both run the same
protocol, which has one shared private source (`packages/core`). Platform packages are
generated from it and stay self-contained when installed.

**Scope: version `1.0.0-beta.1`, nothing published yet.** Plans are numbered (`01-…`, `02-…`)
and tracked in git; `plans/01-repo-structure.md` owns the repository layout and its phases.

This file is the root agent guidance. `.agents/` is the single source of truth for
repository-specific AI instructions: `AGENTS.md` and `CLAUDE.md` are symlinks to
`.agents/AGENTS.md`, and `.cursor` is a symlink to `.agents` — never duplicate instruction
content outside `.agents/`.

## Commands

```bash
pnpm install
pnpm sync               # regenerate every platform copy from packages/core
pnpm sync:check         # fail when any generated file is stale
pnpm typecheck          # tsc, checkJs over scripts, tests, index.js and client.js
pnpm test               # node:test over packages/*/tests and scripts/tests
pnpm lint               # Biome
pnpm lint:fix           # Biome with fixes (the formatter's house style: double quotes, semicolons)
pnpm check:parity       # every shipped protocol has the same five ⏸ gate lines
pnpm check              # sync:check + typecheck + test + lint + check:parity
pnpm set-version <v>    # one version in the root, every package and plugin.json (refuses a lower one)
pnpm pack:packages      # Claude plugin tarball + Harness tarball into artifacts/ (git-ignored)
pnpm readme:check       # README structure: EN/VI/CN parity, absolute links, H1 = unit name
pnpm release:check      # check + readme:check + pack:packages (no publish)
```

## Hard boundaries

- **Edit the source, never the copy.** Generated files carry a "Generated by packages/core"
  note: `packages/claude/skills/zla-flow/SKILL.md`, `packages/claude/config/coder.example.json`,
  `packages/deepseek-harness/protocol.js`, `packages/deepseek-harness/config/coder.example.json`,
  `packages/deepseek-harness/icon.svg`, and the `CODER_TEMPLATE` block in
  `packages/deepseek-harness/client.js` (between its `@generated-start` and `@generated-end`
  markers). Change `packages/core`, run `pnpm sync`, commit both. `pnpm sync:check` fails
  when a copy is stale.
- **Platform packages are self-contained.** Nothing at runtime imports from `packages/core`;
  an installed plugin has no repository around it. Core is a build-time source only.
- **Gate parity.** Every platform carries the same five ⏸ gate lines, word for word. Platform
  differences live only in `packages/core/platforms/<platform>/*.md` fragments.
- **The protocol names no vendor.** Any provider, model, or CLI the session can reach may be
  planner, reviewer, or coder. Never read, print, store, or commit an API key; config files
  hold the **name** of an environment variable.
- **The workflow never skips approval.** A gate is recorded only when the user approved it in
  the conversation. Do not weaken a gate, reorder phases, or infer an approval from files.
- **No build step for the Harness.** `index.js` and `client.js` are loaded from source by the
  host: plain JavaScript (no JSX, no bundler), ESM, JSDoc for types. `client.js` takes React
  from the host module table and styles only from host theme tokens.
- **The Claude plugin is a folder of Markdown and JSON.** No runtime code. `icon.png` is
  rendered by hand from `packages/core/icon.svg` (512 px); re-render it when the icon changes.
- **Naming.** Command, skill, and plugin are `zla-flow`; the project-side folder is
  `.zla-flow/`; npm packages are `@zealagent/plugin-flow-*`. The old `zl-flow`, `zl-build`, `zap-flow`,
  `zealakit`, and `agent-plugins` names must not reappear. Files and folders are `kebab-case`.
- **Code style.** Biome decides formatting. `import type`/JSDoc `@type` for types, strict
  ESM, explicit file extensions. Public behavior needs a test in the owning package.
- **One version.** All packages and `plugin.json` share the root version. Use
  `pnpm set-version`, never hand-edit one file.
- **Documentation.** There is intentionally no `docs/` folder. Product documentation lives only
  in the root README and the package READMEs, following the
  [readme-system skill](skills/readme-system/SKILL.md).
- **Releases.** Manual only. No CI publishing, no bots. **Agents never publish, tag, push a tag,
  or create a release**; they may prepare and run `pnpm release:check` and must say which
  network or marketplace steps they did not run.

## Definition of done

`pnpm check` passes and `pnpm sync:check` reports no stale copy. A change to the protocol or a
platform fragment is checked on both platforms (rendered text and gate lines). Update this file
and the [skill](skills/plugin-flow/SKILL.md) when boundaries, commands, or workflows change.
